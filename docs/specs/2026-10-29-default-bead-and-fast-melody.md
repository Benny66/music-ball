# 默认玻璃珠运动 + 旋律提取提速与缓存

- 状态：已实现并通过技术验收（2026-10-29），待用户视觉确认（006）
- 日期：2026-10-29
- 相关文档：`CONTEXT.md`、`docs/specs/2026-10-28-bead-production.md`、`docs/specs/2026-10-28-melody-worker.md`、`docs/adr/0004-basic-pitch-worker.md`、`docs/adr/0005-bead-performance-trajectory.md`、`docs/adr/0006-bead-default-all-rhythms.md`、`docs/adr/0007-melody-webgl-cache.md`
- 范围：所有节奏来源默认玻璃珠；网格/鼓组用抽稀拍点；钢琴音符升级；Worker WebGL 优先 + CPU 回退；旋律持久缓存
- 不在本轮：多 Worker 分片、WASM/WebGPU、tfjs 升级、FFT 音高、重写节奏/起音分析、玻璃音色重做、经典运动重做、CLI 默认变更

## 1. 问题陈述

用户要的是**页面动画本身**：球自然落体、左右滚动跳动（玻璃珠）。现状只有音符驱动歌能进入玻璃珠；网格/鼓组歌始终是经典运动，加载钢琴歌还要等 basic-pitch 在 CPU Worker 里跑完（168.5s 曲目实测 90.0s）才有音符玻璃珠。音符/网格是**撞点来源**，不应该决定**运动形态**。

本轮要把玻璃珠变成所有歌的默认运动：网格歌第一帧就用拍点驱动，不等模型；钢琴歌先拍点玻璃珠，音符就绪（或缓存命中）后升级为音符玻璃珠。同时把提取从 CPU 90s 压到 WebGL 21s 量级，并用本地缓存让同曲再次加载 0 秒出音符。

## 2. 方案概述

```
任意歌曲
  → 分析（拍点 + 频谱）
  → buildScene(analysis, { motion: 'auto', noteSource? })
       ├─ 有音符（缓存命中 / Worker 完成）→ impactsFromNotes → 音符玻璃珠
       └─ 无音符 → impactsFromBeats（约 1s 抽稀）→ 拍点玻璃珠
  → drawScene（预览 / 浏览器导出 / Node 出片共用）
```

- **运动与撞点解耦**：`motion` 只决定玻璃珠/经典；撞点来源由音符或拍点决定。`auto` 在两种来源下都返回玻璃珠（有至少 2 个可用撞点时）。
- **拍点抽稀**：从真实拍点取约 1s 间隔的最强拍（慢歌逐拍、120BPM 隔一拍、快歌隔两拍），保证相邻撞击 > 最短掉落；左右严格交替；撞击时刻仍精确落在拍点。
- **音符升级**：缓存命中时在首次重建前拿到音符，首个可渲染帧就是音符玻璃珠；未命中时先拍点玻璃珠，Worker 完成且自动判定为音符后，在撞击点用 0.2–0.3s 过渡切到音符玻璃珠。不阻塞播放。
- **提取后端**：Worker 内优先 `webgl`（OffscreenCanvas；tfjs 3.21 需要 `globalThis.window = globalThis` 且关闭 `USE_SETTIMEOUTCUSTOM`），失败/不可用回退 `cpu`，结果与回退原因可见。
- **缓存**：IndexedDB 持久化原始 basic-pitch 音符，键 = 文件内容哈希 + 模型版本；值加载后用当前 onset 重新精修；失败不影响播放/提取。
- **经典回退**：`motion=classic` 仍随时可用；无可用撞点（分析失败/拍点不足）时回退经典并明确提示。

## 3. 用户故事

- **US-01** 任意歌分析完成后，只要存在至少 2 个可用撞点（音符或拍点），首个可渲染帧就是玻璃珠运动；不再先出现经典运动。
- **US-02** 网格/鼓组歌的首个可渲染帧使用拍点玻璃珠，不等 basic-pitch；撞击来自真实拍点，`synthetic` 外推拍点不作为撞击。
- **US-03** 拍点撞击按约 1s 抽稀：相邻撞击间隔 ≥ 最短掉落 + 滚动下限（约 0.9s），优先保留强拍；左右严格交替；撞击时刻精确等于被选中的拍点时间。
- **US-04** 拍点玻璃珠沿用已验收的几何与观感：滚动段原始 0.45–0.75s、最短掉落 0.45s、撞击帧屏幕 58%、滚动段相机不动、掉落段相机先行向下、板子从对应侧入场。
- **US-05** 网格歌无音高：板色来自拍点 `band`，板宽/厚度/弹跳来自 `power`；不跑 FFT 取音高，`midi` 用频段映射（不要求音高准确）。
- **US-06** 钢琴/器乐歌在缓存未命中时，分析完成后先以拍点玻璃珠播放；Melody Worker 在后台提取，播放、seek、调参数不被阻塞。
- **US-07** 音符提取完成且自动判定为音符驱动时，在最近的撞击点把场景升级为音符玻璃珠；切换使用 0.2–0.3s 交叉过渡，播放时间轴不重启、不跳帧；过渡必须通过视觉验收。
- **US-08** 升级期间如果用户手动切到 `classic` 或 `grid`，以用户选择为准；升级不能覆盖手动选择。
- **US-09** 同一文件再次加载且缓存命中时，首个可渲染帧就是音符玻璃珠（无需 Worker、无拍点阶段）；`fileMeta` 明确显示缓存命中。
- **US-10** 缓存按文件内容哈希 + 模型版本隔离；同内容重复加载命中，不同内容/不同模型版本不命中；缓存损坏、配额不足或 IndexedDB 不可用时，不阻塞地降级为正常提取并给出可见提示，不影响播放。
- **US-11** 缓存条目有上限（条目数或字节数）和淘汰策略，避免无限增长；具体上限在实现中定为常量并写入文档。
- **US-12** Melody Worker 优先使用 WebGL 后端（OffscreenCanvas）；WebGL 不可用或推理失败时回退 CPU，UI/日志明确提示回退，CPU 结果仍可用于音符驱动。
- **US-13** 168.5s 真实钢琴曲在硬件 WebGL 下提取目标 ≤30s（headless 探针 21.2s）；CPU 回退保持可用（探针 90.0s）；进度、取消、换歌终止行为不变。
- **US-14** 同一输入下 WebGL 与 CPU 的音符结果逐条一致（起点/音高/力度）；真机硬件 WebGL 若有差异，记录差异并在真实钢琴同步验收中证明不影响起音精修与撞击对拍。
- **US-15** 节奏来源默认仍为 `auto`：钢琴/器乐→音符，鼓组/流行→网格；音符/网格只改变撞点来源，两种都默认玻璃珠。手动 `notes`/`grid`/`classic` 仍生效。
- **US-16** 运动选择器 `auto` 在音符和网格下都选玻璃珠；`bead`/`classic` 可手动覆盖；不再出现“网格/鼓组暂用经典运动”的说明。
- **US-17** 玻璃音轨从当前场景的撞击点生成；网格玻璃珠按 band/power/midi 映射发声；运动切换、音符升级、缓存应用后玻璃轨缓存正确失效，原曲/玻璃/混合三种模式不变。
- **US-18** 预览、浏览器导出、Node 出片共用同一 `buildScene`/`drawScene`；浏览器导出网格歌也走玻璃珠；CLI 在无音符输入时默认仍为经典（保持现有出片默认），显式 `--motion=bead|auto` 时支持拍点玻璃珠。
- **US-19** 玻璃珠模式下，只影响经典运动的控件（速度、密度/stride、物理自由度、seed 等）置灰或标注“仅经典运动”，避免用户拖动后看不到变化。
- **US-20** 真实钢琴全曲（168.5s）首次加载：拍点玻璃珠可播，音符完成后升级；缓存命中后首帧音符玻璃珠；全程预览 60fps，导出可完成。鼓组/流行样例首帧拍点玻璃珠，撞击间隔约 1s，玻璃音轨与拍点同步。
- **US-21** 旧/新视觉对比片通过用户验收：经典 vs 拍点玻璃珠、拍点玻璃珠 vs 音符玻璃珠、升级过渡；用户确认不出现“滑过去”或“瞬移”。
- **US-22** 文档与实现一致：CONTEXT 术语、ADR-0006/0007、README 的限制/性能说明更新；不提交 `fixtures/real`、`out/` 或生成视频。

## 4. 已定决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 默认运动 | 所有节奏来源默认玻璃珠 | 用户要的是动画；音符/网格只决定撞点 |
| 网格撞点 | 真实拍点，约 1s 抽稀，优先强拍 | 保留完整滚动段；120BPM 隔一拍 |
| 音符歌首帧 | 未命中先拍点玻璃珠，命中直接音符玻璃珠 | 不阻塞播放；重复加载 0 秒 |
| 音符升级 | 撞击点 + 0.2–0.3s 过渡，视觉验收 | 减少跳变；不行再退回暂停/跳转切换 |
| 提取后端 | Worker WebGL 优先，CPU 回退 | 168.5s 探针 90.0s → 21.2s，5981 音符逐条一致 |
| 缓存 | IndexedDB 持久，内容哈希 + 模型版本 | 同曲再次加载 0 秒；本地、可淘汰 |
| 节奏来源默认 | 仍为 `auto` | 钢琴→音符，鼓组→网格；不强制全音符 |
| 网格音高 | band/power 映射，不跑 FFT | 稳定、无需新分析；音高感不是本轮目标 |
| 经典运动 | 保留手动回退 | 对照/兜底；不删除旧代码 |
| 拍点选择 | 只用真实拍点，不含 synthetic | 避免无声撞板；长前奏由入场掉落覆盖 |
| CLI 默认 | 无音符时仍 classic；显式 `--motion=bead|auto` 才拍点玻璃珠 | 不改现有出片默认 |
| 缓存失败 | 不阻塞地降级并提示 | 缓存是加速项，不是正确性依赖 |

7. **`src/audio/glass.ts`**：沿用 `notesFromBead`；网格撞击的 midi/band 映射在 `bead.ts` 完成，玻璃轨自然生效；场景变更使缓存失效。
8. **`scripts/render-video.mts` / `scripts/render-bead.mts`**：CLI 默认不变；`--motion=bead|auto` 支持无音符输入；输出与浏览器同场景。

### 测试

- **纯函数**：`impactsFromBeats` 在 60/90/120/140/180 BPM 下的间隔、首尾、强拍优先、左右交替、无 synthetic、少于 2 拍返回空；`buildScene`：网格+auto→bead、网格+classic→classic、网格+bead→bead、无撞点→classic+提示、音符+auto→bead、音符+classic→classic。
- **场景/回归**：`verify`、`verify:note`、`verify:speed`、`verify:bead` 全绿；更新 `verify-scene` 旧期望，新增拍点玻璃珠断言。
- **浏览器 E2E**：真实钢琴首次加载（拍点首帧→音符升级）、同曲二次加载（缓存命中首帧音符）、鼓组样例（首帧玻璃珠、约 1s 撞击）、播放中 seek/换歌/取消、经典切换；断网/禁 IDB 时降级。
- **后端**：WebGL vs CPU 在同一 PCM 上的音符逐条对比（可用调试开关强制 CPU）；WebGL 被禁用时回退 CPU 且提示可见；真机硬件 WebGL 再跑一次。
- **性能**：168.5s 真实钢琴硬件 WebGL 提取 ≤30s；预览 60fps（帧间隔目标 <200ms，完成后 60fps）；缓存命中无 Worker 启动。
- **音频/导出**：网格玻璃珠的玻璃轨时间=撞击拍点；升级/切换/缓存后缓存失效；浏览器导出 1080×1920/60fps 完成；CLI `--motion=bead` 与浏览器同场景。
- **视觉**：旧/新对比片（经典 vs 拍点玻璃珠、拍点 vs 音符、升级过渡）；用户确认；截图/视频不入库。

## 6. 明确不做

- 不做多 Worker 分片、WASM/WebGPU、tfjs 升级；GPU 探针失败才考虑 CPU 分片。
- 不做网格撞击的 FFT 音高检测；不做音高感增强。
- 不改节奏分析、onset 精修、自动判定阈值、basic-pitch 模型版本。
- 不重做玻璃音色配方、混音比例、原曲/玻璃/混合默认行为。
- 不删除/重写经典运动、MDF、旧 `draw`。
- 不做缓存云同步/加密/导出；不做缓存管理 UI（只保留内部上限/淘汰与提示）。
- 不做超长前奏/间奏的幽灵拍点或新球路；视觉验收中发现再单开一片。
- 不改变 CLI 无音符时的默认运动（仍 classic）。
- 不做多球、碰撞、板碎、3D。

## 7. 补充说明

- **探针事实（2026-10-29）**：真实钢琴 168.5s，headless Chromium；CPU Worker `90.0s`，WebGL Worker `21.2s`（4.3x）；两边均 5981 个音符，匹配率 100%，起点/音高/力度差异 0。headless 使用软件 WebGL，真机硬件 WebGL 需再对照；若差异大，回退 CPU 并记录。
- **兼容补丁**：tfjs 3.21 的 `PlatformBrowser.setTimeoutCustom` 直接引用 `window`，Worker 里需 `globalThis.window = globalThis` 且 `tf.env().set('USE_SETTIMEOUTCUSTOM', false)`；这是 3.x 的已知问题，升级 tfjs 前保留补丁与注释。
- **现有验收门**：真实钢琴全曲仍是同步验收门（见 `project-real-piano-sync-acceptance`）；5939 个 basic-pitch 音符/134 次撞击的旧记录是音符玻璃珠基线，本轮网格玻璃珠的撞击数按 BPM/抽稀另记。
- **缓存体积**：5981 音符的 JSON 约 300KB/首；上限建议按 50 首/30MB 取小者，淘汰最久未用。
- **长前奏**：拍点玻璃珠只用真实拍点；第一个撞点前的入场掉落沿用现有 `intro` 行为。若真实样例出现“球悬停太久”，视觉验收记录，下一轮再引入幽灵拍点。
- **升级过渡风险**：两条 BeadPath 在切换点的位置/相机可能不同；若 0.2–0.3s 交叉仍可见跳变，回退为暂停/seek 时应用，并保留“音符已就绪”提示。
- **CLI 边界**：`buildScene` 网格 auto→bead 后，CLI 若显式传 `motion: 'auto'` 且无音符会得到拍点玻璃珠；默认仍是 `classic`，文档写明。

## 8. 完成定义

- 任意歌分析后的首个可渲染帧是玻璃珠（无撞点除外）；网格歌不等 basic-pitch。
- 钢琴歌：缓存命中首帧音符玻璃珠；未命中先拍点、后升级；升级/手动切换不重启音频、不跳帧。
- 168.5s 真实钢琴硬件 WebGL 提取 ≤30s，CPU 回退可用；同曲二次加载缓存命中原帧音符；WebGL/CPU 结果对照记录在案。
- 拍点玻璃珠撞击间隔 ~1s、左右交替、滚动/掉落参数不回归；鼓组样例玻璃音轨与拍点同步。
- 经典回退、CLI、浏览器导出、三种音轨模式不回归；现有测试全绿，新增测试覆盖本 spec。
- 旧/新对比片通过用户视觉验收；CONTEXT、ADR-0006/0007、README 与实现一致；真实音频/生成物不入库。

## 9. 实测记录（2026-10-29，headless Chromium）

- **真实钢琴 168.5s，首次加载**：分析 ~0.6–1.0s；WebGL 提取 13.5–18.9s（多次样本）；5939 个模型音符 → 134 次音符玻璃珠撞击；首帧拍点玻璃珠，音符就绪后在撞击点用 0.26s 过渡升级；`fileMeta` 显示「即将切到/已切到音符玻璃珠」。
- **同曲缓存命中**：0.73–1.01s 完成加载（只跑分析），不启动 Worker，首帧即音符玻璃珠（134 次撞击）。
- **piano-90 对照**：WebGL 5.7s vs CPU 37.1s；两边 1147 个音符逐条一致（起点/音高/力度最大差 0）。
- **真实曲后端对照**：全曲探针 CPU 90.0s vs WebGL 21.2s（原始 5981 音符逐条一致）；应用内 onset 精修后 5939 个。
