# 玻璃珠运动生产化（音符驱动优先）

- 状态：已实现并通过全曲技术验收，待用户确认观感（BP-006）
- 日期：2026-10-28
- 相关文档：`docs/specs/2026-10-28-bead-prototype.md`、`docs/adr/0005-bead-performance-trajectory.md`、`CONTEXT.md`
- 范围：**音符驱动**（钢琴/轻音乐）默认玻璃珠；网格/鼓组保留经典运动；旧运动保留切换/回退
- 不在本轮：网格/鼓组玻璃珠、音频音色重做、MDF 删除、全曲自动调参、生产 UI 大改

## 1. 问题陈述

原型已经验证：球在板上滚动、掉落后自由落体到下一块板、严格左右交替、撞击帧 58%、板子入场。用户观看 8 秒预览与 18 秒新旧对比后确认采用。

生产环境仍走旧的 `buildChart` + `draw`：相机跟着拍点 y 的弦线，球被钉在 58% 附近上下弹，板子只是撞击触发器。需要把原型运动接入预览、导出、音频与待应用旋律，同时保留经典运动作为回退。

## 2. 方案概述

```
音符驱动歌曲
  → melodyResult.notes（Worker）
  → impactsFromNotes(minGap 0.7)
  → buildBeadChoreography（滚动 + 掉落 + 板入场 + 相机）
  → drawBead（浏览器预览 / WebCodecs 导出 / Node 出片共用）

网格/鼓组歌曲
  → 现有 buildChart + draw（经典运动，不变）
```

场景层负责选择：

```ts
type Motion = 'bead' | 'classic';
interface Scene {
  chart: Chart;          // 时间轴、统计、经典回退、音频时长
  bead: BeadPath | null; // 音符驱动 + 玻璃珠时存在
  motion: Motion;
}
```

- `auto`：音符驱动 → 玻璃珠；网格/鼓组 → 经典。
- `classic`：强制经典运动（音符驱动也可回退）。
- 网格驱动本轮不做玻璃珠；选择玻璃珠时自动回退经典并提示。

## 3. 用户故事

- **US-01** 音符驱动歌曲加载完成后，预览默认使用玻璃珠运动：撞击时刻等于抽稀后的音符起音，左右严格交替。
- **US-02** 玻璃珠运动沿用已验证参数：滚动段原始 0.45–0.75s、最短掉落 0.45s、`minGap` 0.7s、撞击帧屏幕 58%、掉落段相机先行向下。
- **US-03** 网格/鼓组歌曲保持现有经典运动；现有 `verify` 的图表/落点/对拍不回归。
- **US-04** 参数面板提供“运动：玻璃珠 / 经典”选择；音符驱动默认玻璃珠，经典可回退；网格驱动显示经典且不可切玻璃珠。
- **US-05** 切换运动不改变当前音频、播放位置与 seek 行为；播放中切换不产生跳帧或音频重启。
- **US-06** 玻璃音轨按玻璃珠撞击点生成（时间、音高、力度、声像），原曲/玻璃/混合三种模式不变；切换运动后玻璃轨缓存正确失效。
- **US-07** 播放中待应用旋律（Worker 完成）应用时，同时重建玻璃珠路径；仍遵守“暂停/seek/播完再应用”。
- **US-08** 浏览器导出与 Node 出片使用与预览相同的场景与 `drawScene`；同一输入/seed 逐帧一致。
- **US-09** 真实钢琴全曲（168.5s）预览 60fps、导出可完成；玻璃珠撞击数、滚动/掉落时长符合本 spec；经典模式可对照。
- **US-10** 旧运动代码保留，可回退；生产默认不删除 MDF/音频/Worker 现有能力。

## 4. 已定决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 生产范围 | 先只覆盖音符驱动 | 原型只在真实钢琴验证；网格鼓组的滚动/掉落密度未验证 |
| 默认运动 | 音符驱动玻璃珠，网格经典 | 用户已采用；不破坏鼓组体验 |
| 回退 | 经典运动保留并可选 | 出问题可回退，便于对照 |
| 撞击密度 | 沿用 `minGap=0.7s` | 与已验收原型一致；后续按曲风再调 |
| 滚动/掉落 | 0.45–0.75s / ≥0.45s | 已验收的慢曲观感 |
| 相机 | 撞击帧 58%；滚动段不动，掉落段先行向下 | 球从上方落进板面，避免“被拉回”的上升感 |
| 左右/音高 | 严格左右交替；音高只影响宽/厚/颜色/落距 | 用户已确认 |
| 空中的掉落 | 确定性抛物线烘焙，不做自由物理引擎 | seek/导出可复现 |
| 音频 | 玻璃音轨按玻璃珠撞击点生成 | 所听即所得；不改玻璃音色配方 |
| MDF | 仅经典模式使用；玻璃珠模式用自身时长 | 两套运动不混用速度模型 |
| 生产代码 | 原型核心移入 `src/`，spike 不再被生产引用 | 避免生产依赖 spike |

## 5. 接缝与测试

### 接缝

1. **`src/chart/bead.ts`**：从 `spike/bead/choreography.ts` 生产化；保留纯函数 `impactsFromNotes` / `buildBeadChoreography` / `evalBead` / `evalBeadCamera` / `evalBeadRoll` / `evalBoardEntry`。
2. **`src/chart/scene.ts`**：`buildScene(analysis, opts)`；根据 `rhythmEffective`、`motion`、`notes` 选择 `bead`/`classic`。
3. **`src/render/bead.ts`**：从 spike 移入 `drawBead`；`SceneScratch` + `drawScene` 分派经典/玻璃珠。
4. **`src/audio/glass.ts`**：`notesFromBead(path)`；玻璃轨从当前场景撞击点生成。
5. **`src/export/mp4.ts`**：改为接收 `Scene` + `SceneScratch`，逐帧 `drawScene`。
6. **`scripts/render-video.mts`**：支持 `--motion=bead|classic` 与 `--notes=<json>`；无音符/网格输入默认经典。
7. **`src/main.ts`**：场景状态、运动选择、待应用旋律、玻璃缓存失效、预览/导出分派。
8. **浏览器/Node 出片**：同一 `drawScene`，同分辨率/帧率。

### 测试

- 纯函数：现有 `verify:bead` 全绿；生产化后测试路径改为 `src/chart/bead.ts`。
- 场景：音符驱动 + auto → bead；网格 + auto → classic；音符驱动 + classic → classic；网格 + bead 请求 → classic + 提示（纯函数/单测）。
- 经典回归：`verify` 5/5、`verify:note` 25/25、`verify:speed` 13/13 不变。
- 音频：`notesFromBead` 的时间/音高/力度/声像；玻璃轨缓存随场景失效；三种音频模式可播。
- 待应用：播放中 Worker 完成 → 先缓存；暂停/seek/播完应用玻璃珠；不跳帧。
- 导出：浏览器导出 vs Node 出片同场景 framemd5 一致；玻璃珠撞击帧 58%。
- 真实曲：全曲 168.5s 预览 60fps、导出完成；玻璃珠撞击数/时长；经典对照；用户确认。
- 性能：全曲玻璃珠路径构建 <50ms；主线程无长任务；导出可取消。

## 6. 明确不做

- 不做网格/鼓组玻璃珠；不做按曲风自动选择玻璃珠参数。
- 不改玻璃音色配方、混音比例、原曲默认/手动切玻璃的现有行为。
- 不删除 MDF、经典运动或旧 `draw`；不重写音频/Worker。
- 不改音符/拍点分析、onset 精修、自动判定。
- 不做多球/复杂碰撞/板碎/3D。
- 不把 spike 的 `out/bead`、真实音频、生成视频入库。

## 9. 实测记录（2026-10-28）

- 真实钢琴全曲（168.5s）：5939 个 basic-pitch 音符，音符驱动玻璃珠 134 次撞击。
- 浏览器预览播放中帧间隔：平均 16.6ms，p95 16.7ms，max 16.8ms。
- 全曲浏览器导出：168.576s，1080×1920@60fps，118MB，成功下载；玻璃珠撞击帧 58% 断言通过。
- 全曲玻璃音轨 134 个撞击音（RMS 0.104）；切回经典后按 681 块板重算，缓存正确失效。
- 网格歌曲（steady-120）：自动经典，玻璃珠选项禁用；Node 经典出片与改动前视频流 framemd5 一致。
- Node `--motion=bead --notes=...` 出片与原型 8 秒预览视频流 framemd5 一致。
- 当前待用户确认全曲观感；确认后再决定是否把默认范围扩展到网格/鼓组。
