# 钢琴独奏：音符驱动与轨迹表现力

- 状态：已实现（2026-10-28）
- 日期：2026-10-28
- 相关文档：`CONTEXT.md`、`docs/adr/0001-note-onset-timing.md`
- 范围：浏览器预览与浏览器导出；输入仅承诺纯钢琴独奏

## 1. 问题陈述

输入纯钢琴独奏时，板子的撞击时刻仍然来自拍网格，而不是音符起音。切分、装饰音、自由速度被均匀网格抹平，玻璃敲击也落在音乐没有起音的位置。用户看到的是「球按拍子走」，而不是「球砸在琴键上」。

具体缺口：

- **音符驱动没有可靠生效**：自动判定使用 `melody.length >= 40 && kickRatio < 0.45`（`src/main.ts:225-228`）。钢琴左手低音会被 `classifyBand` 归为 kick，`kickRatio` 容易被推高；短曲也容易被 40 个音符的门槛挡住。
- **手动切换不生效**：`#rhythm` 改变时只调用 `rebuild()`（`src/main.ts:526-528`），而 `rhythmEffective` 只在 `updateRhythm()` 里计算（`src/main.ts:216-230`）。即使用户选「音符」，实际仍按旧模式出图。
- **模型失败会静默降级**：`extractMelody()` 失败时返回 0.1 秒帧移的 FFT 旋律（`src/analysis/melody.ts:94-97`）。它的起音精度实测只有约 33% 落在 30ms 内，拿它当时间基准会制造新的不同步。
- **轨迹与音乐无关**：横向目标由 seed 随机扫掠生成（`src/chart/build.ts:446`），音符 `amplitude` 只用于判断「是不是旋律」；弹跳高度由和弦规模/时值决定，没有进入力度维度。因此画面即使撞对了时刻，也没有「跟着音乐起伏」的感觉。
- **模型时刻本身有偏差**：basic-pitch 在重叠音/长音上会把起点提前 60–80ms，并把长音谐波识别成额外音符；只信模型时板时间 p90 约 138ms，长音段会出现假撞击。

解决它值得做什么：同步是这个项目的核心承诺；钢琴/轻音乐是明确的目标输入。先把「纯钢琴独奏」这一条路径做对，才能再谈更杂的素材。

## 2. 方案概述

采用**音符驱动模式**：

```
basic-pitch 音符事件
  → 音频 onset 精修        (模型起点吸附到真实起音；无起音的谐波/多检丢弃)
  → 起音/和弦分组          (和弦板：t、主导音高、力度)
  → boardsFromNotes        (合并密集起音、过滤装饰音、计算 power)
  → buildChart(noteSource) (拍网格只提供小节相位/强弱/特殊板)
  → 主导音高轮廓 → 横向目标 → 物理烘焙
  → draw / 播放 / 浏览器导出 / 玻璃音轨
```

拍网格继续存在，但在音符驱动下不决定撞击时刻。没有起音的长音段用幽灵板维持连续运动，不按网格补板。

模型负责音高/和弦，音频负责精确时刻：basic-pitch 起点吸附到宽频 onset（±160ms），窗口内没有起音的音符视为长音谐波/多检丢弃。

自动判定负责挑选模式，用户可手动覆盖。判定顺序：模型不可用 → 网格；鼓组优先（高频瞬态占比 ≥0.09）→ 网格；否则音符。模型不可用时给出可见提示，而不是悄悄退到 FFT 旋律。

表现力只做两件事：**力度/和弦规模驱动弹跳高度、板宽与撞击强度；主导音高轮廓驱动横向走向**。音区颜色沿用现有映射；音符驱动的玻璃音高改用板的主导音高，网格驱动仍用 `midiAt`。

## 3. 用户故事

### 模式选择

- **US-01** 作为用户，加载纯钢琴独奏后，界面明确显示当前是「音符驱动」，并说明判定依据（如「未检测到稳定鼓组，使用音符起音」）。
- **US-02** 当曲目存在稳定、周期性的鼓组时，自动模式保持「网格驱动」，即使 basic-pitch 也能提取出音符；现有流行歌的视觉身份不变。
- **US-03** 用户手动切换「节奏来源」时，图表立即按新选择重建，不需要重新加载文件；切回「自动」会重新走判定。
- **US-04** 音符驱动模式下，密度（stride）控件被禁用并说明原因；网格模式保持原行为。
- **US-05** basic-pitch 不可用、加载失败或音符不足时，自动/手动都不会进入音符驱动；界面显示「旋律模型不可用，已回退节拍驱动」，且不会把 FFT 旋律当时间基准。

### 事件同步

- **US-06** 每块保留下来的板都对应一个真实起音：板时间与该起音的偏差中位数 ≤ 10ms、p90 ≤ 30ms，且不存在「板时间附近没有任何起音」的板。浏览器 basic-pitch 路径先经过音频起音精修；精修后休止段不出现假板，长音持续段允许少量模型谐波多检并记录实际数量。
- **US-07** 起音间隔 ≥ 125ms、时值 ≥ 80ms 的音符都能得到一块板；快速跑动/装饰音允许合并，不要求一音一板。
- **US-08** 起音差 ≤ 60ms 的音合成一块和弦板；和弦板的宽度/高度随和弦规模单调增加。
- **US-09** 起音间隔 < 125ms 时合并，且保留其中力度最强的起音；合并后的全曲板间隔仍 ≥ 125ms（≤ 8 板/秒）。
- **US-10** 没有起音的长音/休止段用幽灵板维持运动，不画板、不发声；下一个起音到来时球重新落在真实板上。
- **US-11** 玻璃音轨的敲击时刻与板的时刻一致（幽灵板除外）；预览与浏览器导出播放同一份音轨。

### 轨迹表现力

- **US-12** 力度（basic-pitch `amplitude`）越高，球从板上弹起越高、板越宽、撞击特效越强；在正常音域内保持单调关系。
- **US-13** 主导音高（和弦最高音，折回 C4–C6）上行时球向右移动，下行时向左移动；相邻板的音程越大，横向位移越大。超过 24 半音的跳变按模型八度/谐波错误处理。
- **US-14** 音高不变时球基本垂直下落；接近赛道边界时回中力生效，球不会贴墙或出界。
- **US-15** 同一输入、同一 seed 下，音符驱动的图表完全可复现；`draw()` 不引入 `Math.random` / `Date.now`。

### 回归与范围

- **US-16** 现有 5 个 `verify` 用例全部通过；同一 seed 下网格驱动的图表与改动前一致。
- **US-17** 浏览器导出使用与预览相同的 `Chart`；导出的画面与音轨保持现有 AAC priming 校准后的同步。
- **US-18** 命令行出片仍走网格驱动；README 明确写出这一限制。

## 4. 已定决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 时间基准 | 音符/和弦起音为唯一基准；网格不参与定板 | ADR-0001；切分、装饰音、自由速度只有起音能表达 |
| 起音精修 | basic-pitch 起点吸附到宽频 onset（±160ms）；无起音的音符丢弃 | ADR-0002；模型在重叠音/长音上提前 60–80ms 并多检谐波 |
| 自动判据 | 高频瞬态占比 ≥0.09 → 网格；否则音符 | 实测钢琴 0.04–0.06，流行/鼓组 0.11–0.26 |
| 启用方式 | 自动判定 + 手动覆盖 | 目标用户不想每次手选，但自动误判必须有逃生口 |
| 自动优先级 | 稳定鼓组 → 网格；否则 → 音符 | 保护现有流行歌的强拍观感 |
| 输入范围 | 仅纯钢琴独奏；轻音乐/带鼓/人声不承诺 | basic-pitch 在独奏钢琴上最可靠；先做对一条路径 |
| 模型失败 | 回退网格 + 明确提示 | 粗粒度 FFT 旋律当时间基准只会更不同步 |
| 和弦窗口 | 起音差 ≤ 60ms 合板 | 与现有 `boardsFromNotes` 的 `chordWindow` 一致 |
| 密集起音 | < 125ms 合并，优先强起音 | 维持 ≤ 8 板/秒的物理上限 |
| 密度控件 | 音符模式禁用；网格模式保留 | 防止定板后又被 stride 抽稀 |
| 力度映射 | 力度/和弦规模 → 弹跳高度、板宽、撞击强度 | 用户选择「力度 + 音高轮廓」档 |
| 音高映射 | 主导音高（和弦最高音，折回 C4–C6）→ 横向；上行右、下行左，步长随音程，带回中力；>24 半音跳变忽略 | 观感像球在跟随旋律；折回与跳变压缩避免模型八度/谐波把球甩到墙上 |
| 颜色/音高 | 音区颜色沿用；音符驱动的玻璃音高用板的主导音高，网格仍用 `midiAt` | 与横向共用同一条旋律音高，避免玻璃声落在低音上 |
| 时值/乐句能量 | 本轮不做新增映射 | 控制调参面与回归风险 |
| CLI | 不做音符驱动 | basic-pitch 在 Node 端需要额外适配；本轮只保证浏览器 |

## 5. 测试决策

### 接缝

优先复用现有接缝，只新增一个纯判定函数：

1. **`selectRhythmMode(analysis, melodyResult, userChoice) -> { mode, reason }`**（新增纯函数）
   把 `updateRhythm()` 的判定逻辑从 UI 中抽离。输入 `AnalysisResult`、`MelodyResult`（含 `source`）与用户选择；输出模式与可展示的原因。Node 里可直接测，不需要 DOM。
2. **`boardsFromNotes(notes, opts) -> NoteBoard[]`**（扩展现有函数）
   直接喂真值音符，测试合板、密集合并、主导音高与力度输出。`NoteBoard` 需要携带 `midi`（主导音高）与 `dyn`（力度），供后续横向/高度映射使用。
3. **`buildChart(analysis, { noteSource }) -> Chart`**（现有接缝）
   主测试面：事件对齐、幽灵板、横向方向、弹跳高度、确定性。绝大多数断言都落在这里。
4. **`notesFromChart(chart, melody) -> GlassNote[]`**（现有接缝）
   断言玻璃敲击时刻与板时刻一致（幽灵板除外）。
5. **`extractMelody(pcm, sr)`**（浏览器专属接缝）
   Node 里无法跑 basic-pitch（依赖 `OfflineAudioContext`），所以模型路径用一次可复现的浏览器检查覆盖：加载合成钢琴 fixture，读取 `window.__musicball` 暴露的旋律、`analysis.onsets` 与图表，核对音符起音与板时间。调试入口还提供 `loadFromUrl()` 与 `seek()`，便于 headless 复现。
6. **`snapNotesToOnsets(notes, onsets, window=160ms)`**（新增纯函数）
   模型音符吸附到音频 onset；窗口内没有起音的音符丢弃；onsets 为空时原样返回。Node 直接测。
7. **`scripts/verify.mts` / `scripts/verify-note.mts`**（现有与新增回归接缝）
   保留现有 5 个用例；新增钢琴音符、力度/音高映射、静音段、自动判定与起音精修用例。

### 测试用例与断言

**A. 音符事件对齐（Node，真值音符 → `buildChart`）**

- 新增合成钢琴 fixture，包含：切分、装饰音/快速跑动、自由速度（rubato）、长音、休止。
- 真值 JSON 含每个音符的 `t / midi / dur / amp`，由生成脚本写出，不依赖版权音频。
- 板精度：每块保留板到最近真值起音的距离，median ≤ 10ms，p90 ≤ 30ms，100% ≤ 50ms。
- 召回：起音间隔 ≥ 125ms 且时值 ≥ 80ms 的真值音符，≥ 95% 得到板。
- 和弦：60ms 内同时起音只产生一块板。
- 密集合并：全曲相邻板间隔 ≥ 125ms；<125ms 的簇中，板的力度不低于簇内最强起音的力度。
- 休止/长音：没有起音的时间段不产生非幽灵板；球的状态连续、无 NaN。

**B. 轨迹映射（Node）**

- 方向：在未触及赛道边界、且 `|Δpitch| ≤ 24` 的相邻板对中，`Δpitch > 0` 时 `Δx > 0`，`Δpitch < 0` 时 `Δx < 0`；符号一致率 ≥ 90%。
- 幅度：`|Δpitch|` 与 `|Δx|` 的 Spearman 相关系数 ≥ 0.7；`|x|` 始终 ≤ 赛道半宽。
- 稳健性：`|Δpitch| > 24` 视为模型八度/谐波错误，横向保持；12–24 半音用 tanh 压缩。
- 力度：`amplitude` 与弹跳高度 `h` 的 Spearman ≥ 0.7；和弦规模与板宽单调不减。
- 确定性：同输入同 seed 连续构建两次，序列化后的 `Chart` 完全相等。

**C. 自动判定矩阵（Node，`selectRhythmMode`）**

- 4 首合成鼓组 fixture → `grid`；`fixtures/real` 下 5 首流行 → `grid`，`夜的钢琴曲5` → `notes`（本地 `--real` 运行）。
- 合成钢琴 fixture + `source: 'basic-pitch'` → `notes`。
- `source: 'fft-fallback'` → `grid`，`reason` 为模型不可用。
- 音符数/密度不足的短曲 → `grid`，`reason` 可展示。
- 手动选择优先级：用户选 `notes` 且模型可用 → `notes`；用户选 `grid` → `grid`。

**D. 回归（Node）**

- 现有 `verify` 5/5 通过，关键指标不退化（对拍率、中位误差、落点误差、NaN）。
- 网格驱动在相同 seed 下的板数、时间、x、h、angle 与改动前逐项一致（快照或数值对比）。
- 玻璃事件时刻与板时刻一致。

**E. 浏览器检查（手动/可复现）**

- 加载合成钢琴 fixture：界面显示「音符驱动」；basic-pitch 音符经音频 onset 精修后，匹配板时间相对真值 median ≤ 10ms、p90 ≤ 30ms；简单段召回 ≥ 95%；2 秒休止段 0 假板。长音持续段允许少量模型谐波多检，但必须记录实际数量。
- 手动切到「网格」再切回「自动」：图表立即变化，无需重新加载。
- 音符模式下密度控件禁用且解释可见。
- 模拟模型失败（阻断模型请求）：界面出现回退提示，图表为网格驱动。

**F. 真实曲验收（人工）**

- 优先使用本地 `fixtures/real/006.夜的钢琴曲5 - 文武贝.mp3`；用户也可另放 1 首真实钢琴独奏（不入库）。
- 视觉确认：撞击可见地落在琴键起音上；旋律上行时球向右、下行时向左；强弱段有明确的高度差；长音/休止段没有假撞击。

### 完成定义

- 上述 A–D 自动断言全部通过。
- E 的浏览器检查至少执行一次并记录数字。
- F 的真实曲视觉验收由用户确认。
- README 更新：音符驱动适用范围、CLI 限制、如何判断当前模式。
- `CONTEXT.md` / ADR 与实现一致。

## 6. 明确不做

- 命令行 `render-video.mts` 的音符驱动（继续网格，README 写明）。
- 轻音乐（弦乐铺底、轻鼓）、人声流行、全混音的同步承诺；这些素材可手动切模式，但不保证效果。
- 用谱通量起音检测作为模型失败的兜底时间基准。
- 绝对音高 → 横向位置的映射；本轮只用旋律走向。
- 时值/连奏、乐句能量（滑窗 RMS）到视觉的新增映射。
- 玻璃音色配方、音区颜色、鼓组模式的视觉改动。
- 自动延迟校准 UI、导出偏移控件、ETA/进度重做。
- 源分离、多乐器分轨、实时/流式分析。
- 每个装饰音都撞板（密集起音按决策合并）。

## 7. 补充说明

- **自动判定的实测**：`kickRatio` 会把钢琴左手低音误当 kick，不能单独用。最终采用**高频瞬态占比**：钢琴 0.04–0.06，流行/鼓组 0.11–0.26，阈值 0.09。真实语料 5 首流行 → 网格、`夜的钢琴曲5` → 音符。
- **模型起音精修**：basic-pitch 在重叠音/长音上提前 60–80ms，并把长音谐波识别成额外音符。用宽频 onset ±160ms 吸附；窗口内没有起音的音符丢弃。精修只改时刻/过滤，不改音高。
- **浏览器实测（表达性钢琴）**：basic-pitch 精修后 255 个音符；匹配板 median 1.2ms / p90 2.0ms，简单段召回 97.9%；65 块板中 11 块为长音/和弦谐波多检（4 秒长音内 5 块，2 秒休止 0 块）。自动判定 `highRatio=0.057` → 音符；5 首流行 0.11–0.17 → 网格。
- **已知限制**：模型会在长音持续段把谐波当成新起音；本轮接受并记录，后续可用频谱新颖度（起音前后同频能量比）过滤。
- **模型推理耗时**：48 秒素材在无 GPU 的浏览器里约 45–90 秒；进度条会显示。CLI 不跑模型，所以出片快但只有网格驱动。
- **数据契约**：音符驱动的板必须把主导音高与力度带到图表层，避免渲染/物理层重新查询旋律。建议给结点/板增加可选的 `midi` 与 `dyn` 字段，网格驱动保持 `undefined`，不改变旧行为。
- **力度归一化**：basic-pitch 的 `amplitude` 是 0..1 的帧激活均值。映射前按曲目分位数归一化并夹取，避免整首曲子都贴在最低或最高档；网格驱动的 power 公式不动。
- **手动选择语义**：用户选择优先于自动。用户选「音符」但旋律仍在提取时，显示等待状态；提取失败则回退网格并提示。用户未手动选择时，旋律提取完成后自动重新判定一次。
- **修复顺序**：先修 `applyAnalysis` 里「先 `rebuild` 后 `updateRhythm`」的旧模式问题（`src/main.ts:248-252`），再处理手动切换；否则首次加载仍可能用上一首的模式。
