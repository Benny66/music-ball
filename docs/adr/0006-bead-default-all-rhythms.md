# 玻璃珠运动对所有节奏来源默认

状态：accepted（2026-10-29）

背景：2026-10-28 的生产范围只让音符驱动歌进入玻璃珠，网格/鼓组保留经典运动。用户随后明确，他要的是**页面动画本身**——球自然落体、左右滚动跳动——不应该由音符/网格决定。玻璃珠一次完整「滚动 + 掉落」需要约 0.9s，而 120 BPM 的拍间隔只有 0.5s，所以网格驱动必须抽稀撞点。

决定：所有节奏来源默认玻璃珠。网格/鼓组用真实拍点驱动，按约 1s 抽稀（慢歌逐拍、120BPM 隔一拍、快歌隔两拍），优先强拍，撞击时刻仍精确落在拍点；无音高时板色/宽度由拍点 band/power 映射。钢琴/器乐先拍点玻璃珠，音符提取或缓存就绪后升级为音符玻璃珠；节奏来源默认仍是 `auto`（钢琴→音符、鼓组→网格），经典运动保留手动回退。升级在撞击点用 0.2–0.3s 过渡，需通过视觉验收。

备选方案：网格继续经典（用户明确要玻璃珠动画）；所有歌都等音符提取（鼓组/流行不适用，且首次要等模型）；网格逐拍撞击（滚动段被压到约 0.2s，会重现用户否掉的「滑过去」）。

## 后果

- 新增 `impactsFromBeats`；`buildScene` 的 `auto` 不再要求 `noteSource`；`verify-scene` 的网格经典断言需更新。
- 玻璃珠模式下只影响经典运动的控件需要置灰/标注，否则用户会以为滑杆坏了。
- 长前奏/长间奏只用真实拍点，球可能在首撞前悬停；视觉验收记录，必要时下一轮引入幽灵拍点。
- 网格玻璃珠没有音高，板色/宽度只能按频段/力度变化；音高感不是本轮目标。
- 旧/新对比片与真实钢琴全曲仍是验收门。
