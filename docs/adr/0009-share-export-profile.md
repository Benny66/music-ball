# 导出默认改为分享档

状态：accepted（2026-11-03）

背景：浏览器导出固定 10 Mbps、Node 出片固定 CRF 17；168.5s 全曲实测分别约 118MB 和 124MB，长曲或复杂画面可达数百 MB。用户明确这些 mp4 主要发社交平台，要求任何时长都 ≤80MB，且不要在导出界面增加画质选项。真实曲目实测 242–392s，按 3 分钟固定码率折算会让长曲仍然超过 100MB。

决定：两条导出路径统一改为 `分享档`（见 CONTEXT.md）：H.264 High、60fps、AAC 192k、文件总量 ≤80MB。视频码率按曲长反算 `(80MB − 音频) × 8 / duration`，上限 3.2 Mbps；当反算码率低于 2.0 Mbps 时改用 720×1280@60，否则 1080×1920@60。浏览器导出使用目标码率 VBR；Node 出片使用 CRF 20 + `maxrate` 为目标码率的 VBV 上限。若真实素材在 1080p 档出现不可接受的暗部色带/煳边，保 60fps 降到 720p，而不是降 30fps。

备选方案：固定 3.2 Mbps（长曲仍 100–157MB，不满足总量目标）；1080p30（固定 CRF 下体积几乎不降，实测 1080p30 0.92 Mbps vs 1080p60 0.94 Mbps，且牺牲运动平滑）；HEVC/AV1（体积更小，但浏览器编码支持与平台兼容不稳）；导出界面给画质档（用户明确不要）。

## 后果

- 3 分钟成片约 76MB（3.2 Mbps 封顶）；4 分钟约 2.5 Mbps、仍保持 1080p；约 4 分 40 秒以上约 1.4–1.9 Mbps、自动降到 720p。长曲分辨率变化需要在导出界面明示。
- 暗部渐变可能出现色带；2.0 Mbps 的分辨率阈值需用真实歌曲视觉验收后校准。
- 浏览器硬件编码器对目标码率的实际落点可能偏低（有助于体积）；Node 的 CRF+VBV 在复杂段落会被上限压低质量。
- README 的「全曲浏览器导出 118MB」基线与「导出」章节需要更新；验收脚本需增加体积与分辨率断言。
- 真实钢琴同步与运动验收不变，分享档只改变编码参数与导出分辨率，不改变帧内容。

验收（2026-11-03，用户确认「可以」）：真实钢琴 168.5s，浏览器全曲 70.6MB，Node 全曲 34.0MB；20s 同帧对比 VMAF 96.7、最低 94.8，暗部放大无明显色带。
