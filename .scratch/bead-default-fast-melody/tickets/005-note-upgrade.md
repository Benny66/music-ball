# 音符升级与播放中过渡

状态：已完成（2026-10-29）

**Blocked by**: 001, 002, 003, 004

**来源**: `docs/specs/2026-10-29-default-bead-and-fast-melody.md`（US-06–08、US-21）、`docs/adr/0006-bead-default-all-rhythms.md`

## 目标

缓存未命中时，钢琴歌一边播拍点玻璃珠一边提取；音符就绪且自动判定为音符后，在撞击点平滑切到音符玻璃珠——不阻塞播放、不重启音频、不覆盖用户手动选择。

## 涉及层

- [ ] 逻辑：`src/main.ts` 的 `startMelodyFor`/`applyMelodyChart`/`pendingMelodyApply` 改为「升级计划」——Worker 完成且 `rhythmSource='auto'`、`selectRhythmMode` 判音符、`motionChoice` 非 classic 时，构建音符场景并选最近的撞击时刻切换；若没有合适撞击，等到下一个或播完。
- [ ] 渲染：在切换点做 0.2–0.3s 交叉过渡（old/new 两个 scene 同刻评估、alpha 混合；或等效的短过渡）；播放时间轴/seek 不重启；预览与导出共用同一状态机。
- [ ] 逻辑：用户手动切 `grid`/`classic` 时取消升级；手动切 `notes` 时立即/按撞击应用；FFT 降级、模型失败、无音符时保持拍点玻璃珠并提示；缓存命中路径（004）首帧已是音符，不需要升级。
- [ ] UI：`fileMeta`/状态行显示「音符提取中」「音符已就绪，即将切到音符玻璃珠」「已应用音符玻璃珠」；失败/取消有可见提示。
- [ ] 测试：piano-90 等短钢琴素材（提取快）验证首帧拍点→升级；真实钢琴全曲验证提取期间播放/seek/升级；手动覆盖矩阵；监听帧间隔与 audio 时间连续性；录制/截图旧新对比。

## 验收标准

- 加载钢琴素材后立即播放：首个可渲染帧是拍点玻璃珠；提取完成后在撞击点切到音符玻璃珠，音频不重启、播放位置连续、无可见长跳帧；0.2–0.3s 过渡通过视觉验收。
- 手动选择优先：提取期间切 `grid` 或 `classic` → 不自动升级；切 `notes` → 就绪后应用；`motionChoice='classic'` 时始终经典。
- 无音符/FFT 降级/模型失败：保持拍点玻璃珠，提示可见，不出现空画面。
- 缓存命中：首帧音符玻璃珠，不触发升级状态（由 004 覆盖）。
- 真实钢琴全曲：提取期间 60fps；升级处音频与画面时间一致；导出同样走升级后的场景。
- 旧/新对比片（拍点玻璃珠 vs 音符玻璃珠、升级过渡）通过用户确认；不出现「滑过去」或「瞬移」观感。
- `typecheck` / `build` / 现有 `verify*` 全绿。

## 备注

- 若交叉过渡在真实曲上仍可见跳变，回退为「暂停/seek/播完时应用」，并保留「音符已就绪」提示——这是 spec 允许的退化路径，但需在 006 记录。
- 不为了升级而阻塞播放或强制 seek；不自动切换经典运动。
